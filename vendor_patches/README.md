# vendor_patches/

Backs up local compatibility patches applied to this project's vendored sibling repos
(`../DefRec_and_PCM`, `../Pointnet_Pointnet2_pytorch`, `../KPConv-PyTorch`, all cloned outside
this repo per CLAUDE.md's Reference codebase conventions). Those repos are meant to stay
"unmodified upstream" dependencies and are never committed as part of `plant3d-thesis` — but two
of the three needed small, real compatibility fixes to run under this project's modern
torch/numpy/setuptools versions against their original ~2019-2020-era code. Those fixes existed
ONLY as uncommitted working-tree edits in the sibling repos' own local checkouts on the cluster —
found during a full repo audit (2026-10-01) to be the one real gap between what's backed up by
git and what only exists on the cluster's disk. This directory closes that gap.

`Pointnet_Pointnet2_pytorch` needed no patches and isn't represented here — confirmed genuinely
unmodified (`git status --porcelain` empty) during the same audit.

## Files

- **`DefRec_and_PCM.patch`** — applies against commit `5cb7b797099b0d44abcd00860669a5f95812ae22`
  (the pinned commit, per CLAUDE.md). Fixes `PointDA/data/dataloader.py`'s three `np.int` calls
  (removed in numpy>=1.24) to plain `int` — already documented in CLAUDE.md's "DefRec repo
  caveats found when integrating" section.
- **`KPConv-PyTorch.patch`** — applies against commit `d19c575d3fa9fcfd5a74845b5b27aac7e50472c7`
  (the pinned commit). Fixes `cpp_wrappers/cpp_neighbors/` and `cpp_wrappers/cpp_subsampling/`'s
  `setup.py` (replaces removed `numpy.distutils`/`distutils.core` with `setuptools`/
  `numpy.get_include()`) and `wrapper.cpp` (adds explicit `(PyArrayObject*)` casts — modern NumPy
  tightened `PyArray_NDIM`/`PyArray_DATA`/`PyArray_DIM`'s signatures to require this) — already
  documented in CLAUDE.md's Backbones section ("numpy/setuptools version incompatibilities in the
  vendored repo's own ~2020-era C-extension code").

Both were generated via a plain `git diff` inside each sibling repo's own working tree (a tracked
upstream repo with uncommitted local edits, not a git-ignored directory) and verified to match
CLAUDE.md's prose description of each fix exactly before being saved here.

## How to reapply (e.g. after a fresh clone of either sibling repo)

```bash
cd ../DefRec_and_PCM
git checkout 5cb7b797099b0d44abcd00860669a5f95812ae22   # if not already there
git apply /path/to/plant3d-thesis/vendor_patches/DefRec_and_PCM.patch

cd ../KPConv-PyTorch
git checkout d19c575d3fa9fcfd5a74845b5b27aac7e50472c7   # if not already there
git apply /path/to/plant3d-thesis/vendor_patches/KPConv-PyTorch.patch
# then rebuild the C extensions, e.g.:
#   cd cpp_wrappers && sh compile_wrappers.sh
```

## Keeping this directory current

These patches were generated by diffing each sibling repo's ACTUAL current working-tree state
(2026-10-01) — if either sibling repo's local files are touched again (another compatibility fix,
a new numpy/setuptools break, etc.), regenerate the corresponding `.patch` file the same way
(`git diff > vendor_patches/<repo>.patch` from inside that sibling repo) and commit the update,
rather than letting this directory drift stale relative to what's actually running on the
cluster.
